



## 概要

あなたは、シェアサイクルシステムを作成することになった。このシステムは、ユーザーが拠点に存在する自転車を借りたり返したりできるシェアサイクルアプリを提供することが主な役割である。

ユーザーは利用予約を行い、好きな拠点で自転車を借りたり返したりすることができる。
また、ユーザーは自分が過去にシェアサイクルを利用した履歴を時系列順に一覧で見ることができる。

上記の説明では、細かい仕様や具体的な入出力方式はまだ書かれていないことに注意せよ。下記の「詳細な仕様」に基づいて、シェアサイクルアプリの画面に表示するデータを出力するプログラムを実装せよ。

## 採点

構築すべきシステムが複雑なので、一部の種類のクエリに対応すれば正答できる「基本実装」というテストケースが用意されている。基本実装をスキップして応用実装にチャレンジすることもできるが、**まず基本実装が動作することを確認してから応用実装に着手することを強く勧める。**

基本実装のテストケースでは、後述する「利用予約キャンセルクエリ」「返却拠点変更クエリ」「レンタル履歴表示クエリ」「割引対応」が発生しないことが保証される。また、与えられるクエリの個数が少ないことも保証される。

それぞれのクエリが正しく実装されているかを確認するための秘密のテストが用意されているため、もし公開テストケースで満点が取れたとしても、最終的な結果が満点ではない可能性がある。そのため、公開テストケースで満点が取れても、プログラムにミスがないか確認することを勧める。

## 詳細な仕様

### 時刻

- 時刻は `YYYY/MM/DD-hh:mm:ss` 形式で表される。
  - `YYYY/MM/DD` は `YYYY` 年 `MM` 月 `DD` 日であることを表す文字列である。
  - `hh:mm:ss` は `hh` 時 `mm` 分 `ss` 秒であることを表す文字列であり、`00:00:00` から `23:59:59` まで (両端含む) の \\(24\\) 時間表記で与えられる。
  - 時刻を表すそれぞれの数について、与えられる桁数は固定であり、適切に \\(0\\) 埋めされて与えられる。
  - 入力で与えられる時刻は `2000/01/01-00:00:00` から `2099/12/31-23:59:59` まで (両端含む) の範囲に含まれることが保証される。
  - 与えられる時刻はグレゴリオ暦に則ったものである。
  - 閏秒は考慮しない。

### ユーザー

- シェアサイクルを利用するユーザーそれぞれに対して、**ユーザー ID** が付与される。
  - ユーザー ID は、英小文字および数字から構成される \\(3\\) 文字以上 \\(10\\) 文字以下の文字列である。
  - すべてのユーザーは、ユーザー ID によって区別される。つまり、異なるユーザーが同一のユーザー ID を持つことはない。

### 拠点

- 自転車の貸し出しおよび返却を行う場所を **拠点** と呼ぶ。それぞれの拠点に対して、**拠点 ID** が付与される。
  - 拠点 ID は \\(1\\) 以上の整数であり、この値によって拠点 ID が区別される。
    - 拠点 ID の先頭には、余分な \\(0\\) は付いていない。
- それぞれの拠点は、駐輪スペースの数が決まっている。
- ある拠点において、利用可能な自転車が存在するとき、その拠点で自転車を貸し出しできる。
  - 「利用可能な自転車の数」は、その拠点に存在している自転車の数から、その拠点で利用予約されている自転車の数を引いたものである。
- ある拠点において、返却可能な駐輪スペースが存在するとき、その拠点で自転車を返却できる。
  - 「返却可能な駐輪スペースの数」は、その拠点の駐輪スペースの数から、以下の数の合計を引いたものである。なお、「利用予約」および「レンタル」の詳細は後述する。
    - その拠点に存在している自転車の数
    - その拠点で返却が指定されており、かつレンタル中である自転車の数
    - その拠点で返却が指定されており、かつ貸し出し拠点と返却拠点が異なっている、破棄されていない利用予約の数

### 利用予約

- ユーザーが自転車を借りるためには、必ず事前に **利用予約** を行う必要がある。
- ユーザーは自転車の貸し出し希望時刻、貸し出し拠点、返却拠点をあらかじめ指定して予約する。受理されたそれぞれの利用予約に対して、**予約 ID** が付与される。
  - 予約 ID は整数であり、この値によって利用予約が区別される。
  - 受理された時刻が早い利用予約から、順に \\(1, 2, 3, \ldots\\) と予約 ID が割り振られる。
    - 付与された予約 ID の先頭には、余分な \\(0\\) は付いていない。
- 利用予約をすると、以下の処理が行われる。これにより、ユーザーは利用予約どおりに自転車を利用できることが保証される。
  - ユーザーが自転車を借りるまでの間、貸し出し拠点にある自転車が \\(1\\) 台確保される。
  - ユーザーが自転車を返却するまでの間、返却拠点にある駐輪スペースが \\(1\\) 台分確保される。
- 利用予約で指定した時刻を \\(30\\) 分過ぎても貸し出しが行われなかった場合、その利用予約は自動的にキャンセルされ、利用予約が破棄される。
  - 利用予約がキャンセルされたとき、確保していた自転車と駐輪スペースが即座に開放され、他の予約でそれらが利用可能になる。
  - **入力で与えられる全てのクエリは、そのクエリが送信された時刻に破棄されるべき利用予約が全て破棄された後に処理される。**
  - 例: あるユーザーが `09:30:00` に貸し出しを希望する利用予約をしており、その後にこのユーザーが同日の `10:00:01` に、利用予約で指定した拠点で自転車を借りようとした場合を考える。`10:00:01` に利用予約が自動的にキャンセルされて破棄されてからクエリが処理されるため、この時刻に自転車を借りることはできない。
- ユーザーが、利用予約で指定した貸し出し拠点で自転車を借りたとき、利用予約が破棄され、後述する **レンタル** が開始する。
- 以下の場合は利用予約ができない。
  - 利用予約をしようとしたユーザーに対し、破棄されていない利用予約が存在する場合
  - 利用予約をしようとしたユーザーに対し、完了していないレンタルが存在する場合
  - 貸し出し拠点として指定した拠点に、利用可能な自転車が存在しない場合
  - 返却拠点として指定した拠点に、返却可能な駐輪スペースが存在しない場合

### レンタル

ユーザーが自転車を借りて返すまでの一連の流れを **レンタル** と呼ぶ。

ユーザーが自転車を借りたとき、レンタルが開始する。また、ユーザーが自転車を返却したときにレンタルが完了する。

#### 自転車の貸し出し

- 破棄されていない利用予約を持つユーザーは、利用予約で指定した貸し出し拠点で自転車を借りることができる。
- 貸し出し希望時刻よりも早い時間に借りることも可能である。

#### 自転車の返却

- 自転車を借りているユーザーは、あらかじめ指定した拠点で自転車を返却する。
- 自転車を返却したタイミングで **レンタル時間** と **レンタル料金** が確定する。
- **レンタル時間** は、自転車を返却した時刻と借りた時刻との差分である。このレンタル時間によって、後に示す **レンタル料金** を計算する。

#### レンタル料金

- レンタルに対する **基本料金** は、レンタル時間の最初の \\(30\\) 分までが \\(150\\) 円、以降 \\(15\\) 分ごとに \\(100\\) 円が加算される (\\(15\\) 分未満の端数は切り上げ)。
  - 例: レンタル時間が \\(30\\) 分の場合、\\(150\\) 円である。
  - 例: レンタル時間が \\(30\\) 分 \\(1\\) 秒の場合、\\(150 + 100 = 250\\) 円である。
  - 例: レンタル時間が \\(50\\) 分の場合、\\(150 + 100 + 100 = 350\\) 円である。
- 基本実装の **レンタル料金** は、上記で計算された基本料金と一致する。
- 応用実装の **レンタル料金** は、基本料金に割引対応を施して計算される。

### ユーザーによる利用予約のキャンセル (応用実装)

- 応用実装のテストケースでは、ユーザーは自分の利用予約をキャンセルできる。キャンセルが成功すると、利用予約が破棄される。
- 利用予約がキャンセルされたとき、確保していた自転車と駐輪スペースが即座に開放され、他の予約でそれらが利用可能になる。

### 返却拠点の変更 (応用実装)

- ユーザーは自転車のレンタル中に、指定した返却拠点を変更できる。
- 返却拠点を変更すると、変更前の返却拠点で確保されていた駐輪スペースが開放され、変更後の返却拠点の駐輪スペースが \\(1\\) 台分確保される。
- 以下の場合は返却拠点の変更ができない。
  - 返却拠点として指定した拠点が、変更前の返却拠点と同じ場合
  - 返却拠点として指定した拠点に、返却可能な駐輪スペースが存在しない場合

### 割引対応 (応用実装)

- 利用予約または返却拠点の変更のタイミングで返却拠点を指定するときに、次の条件をすべて満たした場合、その拠点で自転車を返却する際の基本料金に \\(x \ \\%\\) の割引を行ったものをレンタル料金とする。
  - 貸し出し拠点と返却拠点が異なる
  - 返却拠点の利用可能な自転車の数が \\(3\\) 台未満である
- より具体的には、自転車を返却した拠点について、「その拠点が貸し出し拠点と異なるかどうか」および「その拠点を返却拠点として最後に指定した時刻の、返却拠点の利用可能な自転車の数」をもとに、割引対応が行われるかが決まる。
- \\(1\\) 円未満の端数は切り捨てて計算する。
- 例: 以下の場合、**`12:00:00` 時点** において拠点 \\(1\\) で利用可能な自転車の数が \\(3\\) 台未満のときに割引を行う。
  - `11:00:00` に利用予約を行い、貸し出し拠点を \\(2\\) に、返却拠点を \\(1\\) に指定
  - `11:20:00` に拠点 \\(2\\) にて自転車を借りる
  - `11:30:00` に返却拠点を拠点 \\(2\\) に変更
  - `12:00:00` に返却拠点を拠点 \\(1\\) に変更
  - `12:30:00` に拠点 \\(1\\) で自転車を返却
    - 割引率 \\(x\\) が \\(7\\) で、割引対応を行う必要があるときのレンタル料金は \\(418\\) 円であり、以下のように求められる。
      - レンタル時間が \\(70\\) 分なので、基本料金は \\(150 + 100 \times 3 = 450\\) 円である。
      - 割引率は \\(7 \ \\%\\) なので、割引適用後は \\(450 \times (1.00 - 0.07) = 418.5\\) 円である。
      - 最後に、\\(1\\) 円未満の端数を切り捨てる。レンタル料金は \\(418\\) 円である。
- 割引率 \\(x\\) は入力で与えられる。基本実装では、\\(x\\) が \\(0\\) であること (割引が行われないこと) が保証される。

## 入出力形式

- プログラムに与えられる入力は、標準入力を介して行われる。
  - 改行コードは `\n` (<LF>) である。最終行の末尾にも改行コードが付与される。
- 入力は、以下のようなフォーマットに従う。
```math
\(x\)
\(n\)
\(a_1\) \(b_1\)
\(a_2\) \(b_2\)
\(\vdots\)
\(a_n\) \(b_n\)
\(m\)
\(q_1\)
\(q_2\)
\(\vdots\)
\(q_m\)
```
- 割引率 \\(x\\) が \\(1\\) 行目に与えられる。\\(x\\) は \\(0\\) 以上 \\(99\\) 以下の整数で与えられる。
  - 基本実装のテストケースでは、 \\(x\\) が \\(0\\) であることが保証される。
- 拠点数 \\(n\\) が \\(2\\) 行目に与えられる。\\(n\\) は \\(2\\) 以上 \\(30{,}000\\) 以下の整数で与えられる。
  - 拠点 ID は \\(1, 2, \ldots, n\\) と順に番号付けられている。
- \\(3\\) 行目以降の \\(n\\) 行にわたって、拠点情報 \\(a_i, b_i\\) が与えられる。
  - \\(a_i\\) は、拠点 \\(i\\) の駐輪スペースの数であり、\\(1\\) 以上 \\(100\\) 以下の整数で与えられる。
  - \\(b_i\\) は、初期状態で拠点 \\(i\\) に存在する自転車の数であり、\\(1\\) 以上 \\(a_i\\) 以下の整数で与えられる。
  - 初期状態では、駐車可能な駐輪スペースが必ず存在することが保証される。より具体的には、\\(a_i\\) の合計は \\(b_i\\) の合計より大きいことが保証される。
- クエリの行数 \\(m\\) が \\(n+3\\) 行目に与えられる。\\(m\\) は \\(1\\) 以上 \\(30{,}000\\) 以下の整数で与えられる。
  - 基本実装のテストケースでは、\\(m\\) は \\(1\\) 以上 \\(1{,}000\\) 以下の整数であることが保証される。
- \\(n+4\\) 行目以降の \\(m\\) 行にわたって、クエリ \\(q_i\\) が \\(1\\) 行に \\(1\\) つずつ与えられる。クエリは「利用予約クエリ」「自転車貸し出しクエリ」「自転車返却クエリ」「拠点情報表示クエリ」「利用予約キャンセルクエリ」「返却拠点変更クエリ」「レンタル履歴表示クエリ」の \\(7\\) 種類が存在する。
- クエリは時系列順で与えられることが保証される。また、クエリが送られる時刻はすべて異なることが保証される。
- 各クエリの詳細なフォーマット及び出力すべき内容は以下に示す。
  - クエリで与えられる拠点 ID は、\\(1\\) 以上 \\(n\\) 以下であることが保証される。
  - クエリで与えられる、予約 ID を表す整数は、\\(1\\) 以上 \\(30{,}000\\) 以下であることが保証される。
    - クエリが与えられた時点では、与えられた整数を予約 ID として持つ利用予約が存在しない可能性がある。

### 利用予約クエリ (基本実装・応用実装)

- 入力
  ```plain
  reserve: {時刻} {ユーザー ID} {貸し出し希望時刻} {貸し出し拠点 ID} {返却拠点 ID}
  ```
  - `reserve:`: 文字列 `reserve:`
  - `{時刻}`: 時刻形式。クエリが送られた時刻。
  - `{ユーザー ID}`: ユーザー ID のフォーマットで与えられる。利用予約をするユーザーのユーザー ID。
  - `{貸し出し希望時刻}`: 時刻形式。自転車の貸し出しを希望する時刻。
    - クエリが送られた時刻よりも後の時刻であることが保証される。
  - `{貸し出し拠点 ID}`: 拠点 ID を表す整数が与えられる。自転車を貸し出す拠点の拠点 ID。
  - `{返却拠点 ID}`: 拠点 ID を表す整数が与えられる。自転車を返却する拠点の拠点 ID。

- 出力
  以下の条件を上から順に確認し、最初に当てはまった条件に対応する処理を実行せよ。
  - クエリで指定されたユーザーが、破棄されていない利用予約をすでに持っている場合、利用予約を受理しない。また、以下のエラーを出力する。
    ```plain
    reserve: too many reservations
    ```
  - クエリで指定されたユーザーに対して、完了していないレンタルが存在する場合、利用予約を受理しない。また、以下のエラーを出力する。
    ```plain
    reserve: renting
    ```
  - クエリで指定された貸し出し拠点に、利用可能な自転車が存在しない場合、利用予約を受理しない。また、以下のエラーを出力する。
    ```plain
    reserve: no bicycles available for rent
    ```
  - クエリで指定された返却拠点に、返却可能な駐輪スペースが存在しない場合、利用予約を受理しない。また、以下のエラーを出力する。
    ```plain
    reserve: no place to return
    ```
  - そうでない場合、利用予約を受理する。さらに、以下の出力を行う。
    ```plain
    reserve: {ユーザー ID} {予約 ID}
    ```
    - `{ユーザー ID}`: 利用予約したユーザーのユーザー ID。
    - `{予約 ID}`: 受理された利用予約の予約 ID を表す整数。

### 自転車貸し出しクエリ (基本実装・応用実装)

- 入力
  ```plain
  rent: {時刻} {ユーザー ID} {拠点 ID}
  ```
  - `rent:`: 文字列 `rent:`
  - `{時刻}`: 時刻形式。クエリが送られた時刻。
  - `{ユーザー ID}`: ユーザー ID のフォーマットで与えられる。自転車を借りるユーザーのユーザー ID。
  - `{拠点 ID}`: 拠点 ID を表す整数が与えられる。ユーザーが自転車を借りる拠点の拠点 ID。

- 出力
  以下の条件を上から順に確認し、最初に当てはまった条件に対応する処理を実行せよ。
  - ユーザーが利用予約を持っていない場合、自転車の貸し出しを行わない。また、以下のエラーを出力する。
    ```plain
    rent: no reservations
    ```
  - クエリで指定された拠点 ID が、利用予約時の貸し出し拠点 ID と異なる場合、自転車の貸し出しを行わない。また、以下のエラーを出力する。
    ```plain
    rent: different from reservation information
    ```
  - そうでない場合、自転車を貸し出す。さらに、以下の出力を行う。
    ```plain
    rent: {ユーザー ID} (from {貸し出し拠点 ID} to {返却拠点 ID})
    ```
    - `{ユーザー ID}`: ユーザーのユーザー ID。
    - `{貸し出し拠点 ID}`: 自転車を貸し出す拠点の拠点 ID。
    - `{返却拠点 ID}`: 自転車が返却される拠点の拠点 ID。

### 自転車返却クエリ (基本実装・応用実装)

- 入力
  ```plain
  return: {時刻} {ユーザー ID} {拠点 ID}
  ```
  - `return:`: 文字列 `return:`
  - `{時刻}`: 時刻形式。クエリが送られた時刻。
  - `{ユーザー ID}`: ユーザー ID のフォーマットで与えられる。自転車を返却するユーザーのユーザー ID。
  - `{拠点 ID}`: 拠点 ID を表す整数が与えられる。自転車が返却される拠点の拠点 ID。

- 出力
  以下の条件を上から順に確認し、最初に当てはまった条件に対応する処理を実行せよ。
  - クエリで指定されたユーザーがレンタル中の自転車がない場合、自転車の返却を受け付けない。また、以下のエラーを出力する。
    ```plain
    return: the user don't rent a bicycle
    ```
  - クエリで指定された拠点 ID が、事前に指定した返却拠点と異なる場合、自転車の返却を受け付けない。また、以下のエラーを出力する。
    ```plain
    return: different destination
    ```
  - そうでない場合、クエリを受理して自転車の返却を受け付ける。さらに、以下の出力を行う。
    ```plain
    return: {ユーザー ID} {料金}
    ```
    - `{ユーザー ID}`: 自転車を返却したユーザーのユーザー ID。
    - `{料金}`: レンタル時間に応じたレンタル料金。

### 拠点情報表示クエリ (基本実装・応用実装)

- 入力
  ```plain
  base: {時刻} {拠点 ID}
  ```
  - `base:`: 文字列 `base:`
  - `{時刻}`: 時刻形式。クエリが送られた時刻。
  - `{拠点 ID}`: 拠点 ID を表す整数が与えられる。情報を表示する拠点の拠点 ID。

- 出力
  - 以下を出力する。
    ```plain
    base: {拠点 ID} {駐輪スペースの数} {利用可能な自転車の数} {返却可能な駐輪スペースの数}
    ```
    - `{拠点 ID}`: クエリで与えられた拠点 ID
    - `{駐輪スペースの数}`: その拠点の駐輪スペースの数
    - `{利用可能な自転車の数}`: クエリが与えられた時点での、その拠点の利用可能な自転車の数
    - `{返却可能な駐輪スペースの数}`: クエリが与えられた時点での、その拠点の返却可能な駐輪スペースの数

### 利用予約キャンセルクエリ (応用実装)

- 入力
  ```plain
  cancel: {時刻} {ユーザー ID} {予約 ID}
  ```
  - `cancel:`: 文字列 `cancel:`
  - `{時刻}`: 時刻形式。クエリが送られた時刻。
  - `{ユーザー ID}`: ユーザー ID のフォーマットで与えられる。利用予約をキャンセルするユーザーのユーザー ID。
  - `{予約 ID}`: 予約 ID を表す整数が与えられる。キャンセルされる利用予約の予約 ID。

- 出力
  以下の条件を上から順に確認し、最初に当てはまった条件に対応する処理を実行せよ。
  - クエリが与えられた時点で、与えられた整数を予約 ID として持つ利用予約が存在しない場合、またはすでに破棄されている利用予約の予約 ID がクエリで与えられた場合、利用予約をキャンセルしない。また、以下のエラーを出力する。
    ```plain
    cancel: unavailable reservation
    ```
  - クエリで与えられたユーザー ID が、キャンセルしたい利用予約を予約したユーザーのユーザー ID と異なる場合、利用予約をキャンセルしない。また、以下のエラーを出力する。
    ```plain
    cancel: unauthorized
    ```
  - そうでない場合、利用予約をキャンセルする。さらに、以下の出力を行う。
    ```plain
    cancel: {予約 ID}
    ```
    - `{予約 ID}`: キャンセルされた利用予約の予約 ID を表す整数。

### 返却拠点変更クエリ (応用実装)

- 入力
  ```plain
  change: {時刻} {ユーザー ID} {返却拠点 ID}
  ```
  - `change:`: 文字列 `change:`
  - `{時刻}`: 時刻形式。クエリが送られた時刻。
  - `{ユーザー ID}`: ユーザー ID のフォーマットで与えられる。自転車を返却する拠点を変更するユーザーのユーザー ID。
  - `{返却拠点 ID}`: 拠点 ID を表す整数が与えられる。自転車を返却する拠点の拠点 ID。

- 出力
  以下の条件を上から順に確認し、最初に当てはまった条件に対応する処理を実行せよ。
  - ユーザーがレンタル中の自転車がない場合、返却拠点の変更を行わない。また、以下のエラーを出力する。
    ```plain
    change: the user don't rent a bicycle
    ```
  - 変更前の返却拠点と同じ拠点を指定した場合、返却拠点の変更を行わない。また、以下のエラーを出力する。
    ```plain
    change: same base
    ```
  - 返却拠点に自転車が返却可能でない場合、返却拠点の変更を行わない。また、以下のエラーを出力する。
    ```plain
    change: no place to return
    ```
  - そうでない場合、クエリを受理して返却拠点を変更する。さらに、以下の出力を行う。
    ```plain
    change: {ユーザー ID} {返却拠点 ID}
    ```
    - `{ユーザー ID}`: 返却拠点を変更したユーザーのユーザー ID。
    - `{返却拠点 ID}`: 自転車が返却される拠点の拠点 ID。

### レンタル履歴表示クエリ (応用実装)

- 入力
  ```plain
  history: {時刻} {ユーザー ID}
  ```
  - `history:`: 文字列 `history:`
  - `{時刻}`: 時刻形式。クエリが送られた時刻。
  - `{ユーザー ID}`: ユーザー ID のフォーマットで与えられる。レンタル履歴を表示するユーザーのユーザー ID。

- 出力
  以下を出力する。
  ```plain
  history: {ユーザー ID}
  {貸し出し時刻 1} {貸し出し拠点 ID 1} {返却時刻 1} {返却拠点 ID 1} ({料金 1} yen)
  {貸し出し時刻 2} {貸し出し拠点 ID 2} {返却時刻 2} {返却拠点 ID 2} ({料金 2} yen)
     ...
  ```
  - 完了したレンタルの履歴を、貸し出し時刻が新しい順に \\(5\\) 件まで出力する。
    - クエリが送られた時点で、完了したレンタルが存在しない場合でも `history: {ユーザー ID}` からなる行は出力すること。
  - `{ユーザー ID}`: クエリで指定されたユーザー ID
  - `{貸し出し時刻 x}`: \\(x\\) 番目に新しいレンタルの、自転車を借りた時刻
    - 時刻形式で出力すること。
  - `{貸し出し拠点 ID x}`: \\(x\\) 番目に新しいレンタルの、自転車を借りた拠点の拠点 ID
  - `{返却時刻 x}`: \\(x\\) 番目に新しいレンタルの、自転車を返却した時刻
    - 時刻形式で出力すること。
  - `{返却拠点 ID x}`: \\(x\\) 番目に新しいレンタルの、自転車を返却した拠点の拠点 ID
  - `{料金 x}`: \\(x\\) 番目に新しいレンタルの、レンタル料金

- `user01` が利用予約をする。貸し出し希望時刻は `2024/01/01-11:00:00` で、貸し出し拠点 ID は \\(1\\) で、返却拠点 ID は \\(2\\) である。
